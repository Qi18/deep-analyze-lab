# DeepAnalyze 实验与学习方案

## 1. 项目定位

**DeepAnalyze 自主数据分析 Agent：部署复现、课程式后训练与效果评估**

学习目标是理解模型如何通过“分析—编程—执行—反馈”完成数据分析；实验目标是测清楚 SFT、Cold Start、GRPO 分别带来了什么，最终形成能演示、能复现、能讲清个人工作的简历项目。

复用上游代码和训练框架。自己的工作集中在数据处理、实验配置、训练复现、评测、失败分析，以及实验中确实需要的代码修改。

本方案替代此前的需求评审和六周候选路线，按实验阶段推进。配套评测协议和报告模板中的旧版本命名、数据划分或阈值如与本文冲突，以本文为准，执行对应阶段时再同步具体配置。

## 2. 八阶段学习与实验路线

建议按下面 8 个阶段推进，约 **8–10 周、每周 8–12 小时**。这是学习与操作时间估算，GPU 运行时间另计。

| 阶段 | 学什么 | 做什么实验 | 留下什么成果 |
|---|---|---|---|
| 1. 部署与推理 | 模型服务、Action 协议、文件执行流程 | 部署官方 DeepAnalyze-8B，跑单表、多文件、清洗、绘图、追问 5 类任务 | 部署说明、完整案例、初始失败清单 |
| 2. 源码与执行反馈 | 推理循环、停止条件、上下文拼接、Python 执行 | 注入文件缺失、代码异常、超时，观察反馈如何影响后续动作 | 调用链笔记、错误轨迹、必要的运行记录补充 |
| 3. 建立评测基线 | 任务断言、数值容差、数据隔离、指标口径 | 固定开发集与测试集，运行官方模型和基础模型基线 | 任务集、评分脚本、基线报告 |
| 4. 数据与训练准备 | 特殊 Token、标签掩码、数据配比、轨迹格式 | 抽样审计官方数据，小模型完成训练与推理验证 | 数据统计、样本审计、可运行训练配置 |
| 5. 单能力 SFT | 监督学习如何教会推理、表格理解和代码能力 | 从 8B 基础权重出发训练，比较训练前后单能力表现 | checkpoint、训练曲线、分能力评测 |
| 6. 多能力 Cold Start | 单项能力如何组合成多轮工具交互 | 使用完整交互轨迹训练，比较多轮成功率与恢复能力 | 轨迹样本、阶段对比、失败案例 |
| 7. Agentic RL | Rollout、环境反馈、Reward、GRPO | 先调通小规模 RL，再运行 8B 实验和奖励消融 | RL 配置、奖励分析、独立测试结果、成本记录 |
| 8. 综合评测与展示 | 泛化、性能、复现和结果表达 | 冻结最终版本，运行测试集、API 演示与性能测试 | 最终报告、演示视频、简历项目描述 |

## 3. 模型与算力路线

保留“小模型调通、8B 正式实验”的安排。小模型用于发现数据和训练流程问题；正式训练从 `DeepSeek-R1-0528-Qwen3-8B` 基础权重开始，官方 DeepAnalyze-8B 用作参考对照。

是否能在 L20 上采用某组 batch、上下文长度和并行配置，要通过预检和短跑确定。

L20 权威工作区为 `/data/projects/deep-analyze-lab`，上游源码保留在 `DeepAnalyze/`。实验保存模型 revision、代码 commit、数据 manifest、命令、配置和原始结果位置。

## 4. 对照版本

实验的核心，是保留每个训练阶段的模型，做同一套评测。

| 版本 | 模型与执行方式 | 要回答的问题 |
|---|---|---|
| Base-direct | 基础模型直接回答 | 不执行代码时能做到什么？ |
| Base-agent | 基础模型 + 上游 Agent 执行流程 | 执行工具带来多少收益？ |
| SFT | 单能力 SFT 后 + 同一执行流程 | 单能力训练改善了哪些任务？ |
| Cold-start | 多能力轨迹训练后 + 同一执行流程 | 多轮分析与工具交互是否改善？ |
| RL | GRPO 后 + 同一执行流程 | 成功率、恢复能力和执行效率是否改善？ |
| Official | 官方 DeepAnalyze-8B + 同一执行流程 | 与官方模型还有哪些差距？ |

训练阶段之间固定测试输入、生成参数和执行预算。直接回答版本需要获得等价的数据内容或可访问的信息；无法公平对照的文件发现、绘图等任务单独报告。

## 5. 评测数据安排

- **开发集 20 个任务**：用于调试 Prompt、工具、训练配置和评分器。
- **独立测试集 30 个任务**：覆盖统计问答、多文件关联、清洗、绘图、错误恢复、数据不足等场景，最终统一运行。
- **安全测试单独建集**：检查文件越界、网络访问和资源限制，避免混入普通任务准确率。
- 按数据来源、表结构或任务模板分组切分，防止同一数据换个问题就同时出现在训练集和测试集。
- 最终版本与主要基线各运行 3 个固定 seed；报告成功数/总数及波动。30 个任务属于小规模离线评测，简历中保留这个范围。

## 6. 指标与结果记录

| 指标 | 用途 |
|---|---|
| 任务成功率、数值正确率 | 衡量是否完成用户问题 |
| 代码执行成功率、失败恢复率 | 衡量工具使用能力 |
| 结论证据覆盖率、无依据结论率 | 衡量报告可信度 |
| 图表正确率 | 检查绘图数据与文字结论是否一致 |
| 平均轮数、Token、耗时 | 判断提升付出了多少成本 |
| GPU 小时、峰值显存 | 记录训练和推理资源成本 |

先测基线，再决定优化目标。不要预先要求自己“必须提升 20%”，也不要根据最终测试结果反复调整模型。

## 7. 三个关键对照实验

1. **单能力 SFT 前后对比**：分析提升来自代码能力、表格理解还是输出格式。
2. **Cold Start 前后对比**：重点看多轮成功率、协议错误和执行失败后的恢复。
3. **GRPO 前后及奖励消融**：在相同执行预算下比较正确性、恢复率和成本，检查模型是否利用奖励漏洞。

## 8. 源码学习与笔记

每个阶段的笔记只回答四个问题：

1. 入口代码在哪里？
2. 数据如何流动？
3. 为什么这样设计？
4. 实验支持了什么结论？

源码学习直接服务于实验和面试。结构化 Trace 是必要时补充的实验记录手段，是否修改执行流程由实际实验问题决定。

## 9. 最终交付

完成后，仓库应能提供：

- 一套可复现的环境、数据处理、训练和评测命令。
- SFT、Cold Start、GRPO 的配置与模型产物记录。
- 各阶段同协议下的效果对比。
- 至少 5 个有解释的失败案例。
- 一个上传文件、自动分析、生成图表和报告的完整演示。
- 一份明确说明个人工作、上游复用范围和实测结果的报告。

模型权重、完整训练数据和大体积原始日志按仓库既有管理方式保存在 Git 外，仓库记录其 manifest 和指标摘要。

## 10. 简历成果转化

以下为完成实验后的表述模板，数字由实验填入，训练阶段仅保留实际完成的部分。

**DeepAnalyze 自主数据分析 Agent｜个人项目**

- 基于 DeepAnalyze 完成自主数据分析系统部署，支持多文件分析、代码执行、可视化及多轮交互，复现从基础模型到单能力 SFT、多能力 Cold Start、GRPO 的后训练流程。
- 构建包含 `[N]` 项任务的独立评测集，对各训练阶段进行统一评估，任务成功率由 `[A]` 提升至 `[B]`，错误恢复率由 `[C]` 提升至 `[D]`。
- 针对 `[具体失败问题]` 完成 `[数据/奖励/执行流程改进]`，通过消融实验验证效果，并记录推理耗时、Token 与 GPU 成本，提供可复现配置和演示。
