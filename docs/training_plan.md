# DeepAnalyze 简历目标导向实验方案

更新时间：2026-09-07

## 0. 方案定位

本方案从应用算法岗/Agent 算法岗简历所需证据倒推实验，不再以“读完源码”或“跑通官方 Demo”为完成标准。最终要能够用本仓库中的代码、配置、评测结果和运行记录支撑下面这句话：

> 基于 DeepAnalyze-8B 开发 LLM 训练实验自动分析 Agent，完成推理闭环改造、受控代码执行、固定评测、领域适配和服务化验证，并用可复现实验量化正确性、可靠性、安全性与效率。

当前仓库仍是实验骨架。本文中的阈值都是目标门槛，不是已经取得的结果；只有 `docs/final_report.md` 中标记为 `verified` 且能定位到原始产物的数字，才允许进入 README 或简历。

执行时间建议为 6 周、每周 8–12 小时：70% 用于实现与实验，20% 用于按调用链阅读源码，10% 用于整理报告。完整 8B SFT/GRPO 不是核心项目完成的前置条件，训练结论必须单独通过训练阶段门。

## 1. 最终项目与个人贡献边界

### 1.1 最终产品

实现一个 **LLM 训练实验自动分析 Agent**，输入包括多次训练的配置、loss、learning rate、吞吐、GPU 指标、checkpoint 和 evaluation 结果，输出包括：

- 自动发现并对齐不同 run；
- 检测 NaN、过拟合、吞吐下降、配置漂移和评测退化；
- 生成可核验的表格与图表；
- 将关键结论绑定到输入文件、字段、计算代码和执行结果；
- 明确不确定性、数据缺失和不可回答项；
- 在代码执行失败后基于受限错误信息恢复；
- 给出有证据的下一步实验建议。

### 1.2 必须形成的个人贡献

| 简历能力 | 必须完成的个人工作 | 最小证据 |
|---|---|---|
| Agent 推理 | 为多轮 Action 增加结构化轨迹、终止原因、耗时和执行状态 | 代码 diff、3 条完整轨迹、状态图 |
| 工具可靠性 | 实现超时、输出截断、错误分类和至少一种恢复策略 | 故障注入结果、恢复率 |
| 安全工程 | 将直接 `exec` 替换或封装为受控执行环境 | threat model、安全回归、越权数 |
| 领域能力 | 完成训练实验对齐、异常诊断和证据引用 | 可运行 Demo、固定任务结果 |
| 评测能力 | 建立版本化任务集、断言、指标计算和基线对比 | manifest、评测脚本、结果 JSON/CSV |
| 部署能力 | 提供 API/WebUI 演示并测量服务指标 | 启动命令、并发测试、资源记录 |
| 训练能力（进阶） | 实际完成 SFT/cold start 或 GRPO 对照实验 | 数据 manifest、曲线、checkpoint、测试集结果 |

“导入上游源码”“阅读论文”“运行官方样例”只能算准备工作，不能作为个人贡献点。

## 2. 对照版本与实验原则

统一使用冻结的模型 revision、评测集版本和生成参数；除主变量外保持环境一致。至少比较：

| 版本 | 定义 | 用途 |
|---|---|---|
| B0 | 基础模型直接回答，不提供代码工具 | 证明工具闭环的价值 |
| B1 | 固定上游 commit 的原始 DeepAnalyze 推理与执行 | 项目主基线 |
| B2 | 本 Lab 的可观察、可恢复、受控执行版本 | 核心工程成果 |
| B3 | B2 + 领域 SFT/cold start（实际训练后才存在） | 验证领域适配收益 |
| B4 | B3 + Agentic RL（实际训练后才存在） | 验证长轨迹策略优化收益 |

实验规则：

1. B0–B2 使用相同模型 revision、prompt、输入和解码参数。
2. 每个非确定性任务固定 3 个 seed，各运行 3 次；报告均值、离散程度和失败样本。
3. 训练集、开发集和最终测试集按任务族隔离；训练期间不得查看或改写测试断言。
4. 所有指标由脚本从原始结果计算，不手工挑选最佳回答。
5. 每项改造只解决一个主问题，并与前一版本做消融对比。

## 3. Resume-Eval-v1 评测集

第一版建立 30 个固定任务，每组 5 个：

1. 单表统计与数值问答；
2. 多 run、多文件关联与配置对齐；
3. NaN、过拟合、吞吐下降和指标退化诊断；
4. 图表生成及图表—数据一致性；
5. 文件缺失、代码异常、依赖缺失和超时后的恢复；
6. 不可回答、路径越权、网络访问、进程/命令越权和提示注入。

每个任务保存 `task_id`、输入 manifest、prompt、允许工具、参考断言、禁止行为、评分器版本和难度。最终测试集至少 10 个任务保持盲测；若执行领域训练，训练数据不得包含这些任务的输入、断言或改写版本。

### 3.1 核心指标

| 维度 | 指标 | 项目目标门槛 |
|---|---|---:|
| 正确性 | answer accuracy | ≥ 80% |
| 证据 | grounded claim rate | ≥ 90% |
| 执行 | code success rate | ≥ 90% |
| 恢复 | recovery rate | ≥ 80% |
| 图表 | plot validity | ≥ 90% |
| 克制 | unsupported claim rate | ≤ 5% |
| 稳定性 | repeated-run consistency | ≥ 85% |
| 安全 | policy violation count | 0 |

同时记录平均 Action 轮数、输入/输出 token、端到端耗时、首 token 延迟、峰值显存和沙箱额外开销。这些效率指标必须报告实测分布，不预设或编造简历数字。

### 3.2 项目价值实验

从盲测集中选择 10 个训练分析任务，让同一名使用者分别采用手工脚本和 Agent 完成，记录任务耗时、正确率和返工次数。目标是：

- 中位完成时间下降至少 50%；
- 正确率相对人工结果下降不超过 5 个百分点；
- 所有结论均可定位到证据；
- 统计初始化、人工熟悉度和失败重试时间。

该实验只是受控离线效率测试，不得表述为线上生产收益。

## 4. 六周执行路线

### 第 1 周：冻结基线并跑通端到端

任务：

- 固定 Lab、DeepAnalyze、模型和运行环境 revision；
- 在 L20 跑通 B0 与 B1；
- 用 6 个 smoke task 覆盖单表、多文件、绘图、错误恢复、不可回答和越权；
- 追踪 `instruction → action → environment → report` 调用链，只阅读实际经过的源码。

产出：环境清单、系统架构图、B0/B1 原始轨迹、基线指标和失败清单。

阶段门 G1：他人可按文档复现一次 B1 任务；基线失败也必须完整记录，不能只保留成功案例。

### 第 2 周：建立可观察性和统一评测器

任务：

- 为每轮 Action 记录类型、耗时、token、代码 hash、执行状态、错误类别和终止原因；
- 建立 Resume-Eval-v1 manifest、参考断言和自动评分入口；
- 生成 B0/B1 的 30 任务结果与聚合指标；
- 对数值、证据、图表和安全指标分别做评分器单测。

产出：结构化 trace、评测脚本、指标 CSV/JSON、首版错误分类。

阶段门 G2：同一结果文件可重复生成相同聚合指标；至少一项可观察性改造形成清晰个人代码 diff。

### 第 3 周：受控执行与故障恢复

任务：

- 建立每会话独立 Workspace；
- 实现容器/受限进程执行、路径白名单、超时、CPU/内存/进程限制和输出截断；
- 默认关闭网络，拒绝凭据、宿主路径和危险命令访问；
- 注入文件不存在、包缺失、Python 异常、超时和超大输出；
- 对比“完整错误”“分类后的受限错误”和“通用失败”三种反馈策略。

产出：threat model、沙箱配置、故障注入集、B2 安全与恢复实验。

阶段门 G3：安全越权数为 0；若恢复率未达门槛，必须给出失败分布和下一步控制变量，不得将沙箱描述为完成。

### 第 4 周：完成训练实验分析 Agent

任务：

- 定义统一 run schema，接入配置、标量日志、GPU 指标、checkpoint 与 evaluation；
- 实现 run 发现、时间/step 对齐、异常规则和证据索引；
- 将确定性解析与计算做成工具，将开放式诊断交给 Agent；
- 输出结论、证据、局限性和建议四段式报告；
- 完成 B1 与 B2 的全量对照和至少 3 个典型案例演示。

产出：领域 Demo、工具说明、报告样例、B1/B2 对照表和失败案例。

阶段门 G4：30 个任务全部有结果；B2 达到核心质量与安全门槛，或对未达指标给出可复现的根因结论。

### 第 5 周：领域训练与消融

先做数据审计和小规模验证，再决定是否扩大训练：

1. 审计 Action token、环境反馈、长轨迹截断、失败轨迹和数据泄漏；
2. 建立领域训练/开发集，先运行小规模 LoRA/SFT 验证数据和损失；
3. 完成 B2 vs B3 对照；
4. 只有 B3 仍存在明确、可由策略学习改善的问题，且 rollout/reward 已通过单测，才启动 GRPO；
5. 比较格式奖励、执行成功奖励、答案/证据奖励的消融结果。

产出：数据 manifest、训练配置、SwanLab 链接、checkpoint manifest、B2/B3/B4 测试结果和成本记录。

阶段门 G5：只有测试集指标优于 B2、且收益不是由安全退化或更长轨迹换来的版本，才能写入“完成 SFT/GRPO 并提升指标”。训练 loss 下降本身不算能力提升。

### 第 6 周：服务化、价值验证与简历证据包

任务：

- 使用 vLLM 提供 OpenAI 兼容 API，保留 Workspace 与沙箱边界；
- 在并发 1/2/4 下测量成功率、吞吐、P50/P95 延迟和峰值显存；
- 完成 10 个任务的人工 vs Agent 受控效率实验；
- 录制一个从上传数据到生成可核验报告的演示；
- 完成最终报告、复现命令、架构图、指标摘要和简历表述审核。

阶段门 G6：新环境能按说明复现核心 Demo；最终报告中的每个数字都有文件路径、实验 ID 和脚本来源；简历只引用 `verified` 结果。

| ID | 优先级 | 实验 | 主变量 | 关键输出 |
